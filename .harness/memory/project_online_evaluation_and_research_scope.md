- Research chain is U850 anomaly → CIO projection → pre-trained LSTM → summer precipitation anomaly; CIO is an indispensable LSTM input, not an optional competing module.
- User-confirmed training design: leave-one-year-out cross-validation over 2000–2019. Future paper drafts should describe this as the training design until the actual training provenance is checked; do not assert that every existing checkpoint was trained on all other 19 years. New U850 data are supported as inference inputs, not a request to retrain.
- Prediction domain is 100–125°E, 20–40°N; the paper focus region is 112–121°E, 23–27°N. U850-only is the intentional checkpoint-compatible configuration; SST is out of scope.
- Keep the pointwise Pearson-r heatmap as the main spatial skill view. Add task-specific focus-region evaluation: regional mean prediction/truth series, regional-series r/RMSE/MAE, mean defined pointwise r, dates/sample count, and CSV export. Do not mix this with the historical 2003 S2S chart.
- Fix scientific labels: call both maps precipitation anomaly; distinguish r=0.5 contour from any precipitation contour; do not claim negative r alone proves worse-than-climatology. The stripe-source investigation is paused until this evaluation change is complete, then resume.
- Stripe investigation resumed 2026-10-01 on the real pre1/2000 diagnostic artifact: raw/processed U850 fields are longitudinally smooth, but `e_u850.reshape(41,81,order='F')` has strong longitude-wise striping and so does `|processed × weight|`. The displayed `mode_U` map is a smooth geographic layout and is not the same array (correlation −0.3007) as the calculation weight map. Preserve the legacy F-order computation because it reproduces official CIO, but do not present its fence-like contribution map as physical geographic evidence; resolve the UI semantics before paper use.
- 2017 audit, identified 2026-10-03: before the local fix, `src/src/prediction.py` had a special `pre_year == 17` branch retaining only the preceding 17 blocks. With 2000–2019 ordered input, this meant training on 2000–2016 for target 2017 and omitting 2018–2019. Whether existing demo 2017 checkpoints were generated by that version is still UNVERIFIED; do not infer checkpoint provenance from the local script alone.
- Local source fix on 2026-10-04: `prediction.py` now calls `year_split.split_leave_one_year_out` to retain every complete year block except the target, with paired-series/year-range validation. `src/src/test_year_split.py` passed 28 tests covering all 20 targets (each has 19 × 112 training samples and 112 held-out samples), other year counts, and invalid input. Run from `src/src`: `python -m pytest test_year_split.py -q -p no:cacheprovider`. This local source change has NOT retrained, replaced, or established the provenance of any checkpoint; transfer both training source files if training happens on the original server. Research `src/` is excluded by the website repository's current `.gitignore`.
- Before reporting 2017 or pooled results as full leave-one-year-out experiments, check the actual checkpoint-generating script and training logs/year lists. If the 17-year branch was used, either retrain and reevaluate the affected models/results with the intended 19 years, or explicitly report the deviation and actual training years. A shorter phrase such as “leave-one-year-out training design” does not authorize hiding an implementation exception.
- Separate audit boundary: the local legacy training script normalizes CIO and precipitation on the complete supplied series before the year split. Excluding the target year's optimization samples does not establish test-independent preprocessing; verify normalization/EOF/climatology provenance before claiming a leakage-free or strictly operational evaluation.
