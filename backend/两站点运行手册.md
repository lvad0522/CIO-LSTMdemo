# 两站点运行手册（fold1 / foldmax）—— 保姆级

> 本文回答一件事：**怎么同时开两个页面，一个折 1 口径、一个折最大口径，分别看什么。**
> 口径本身为什么这么定，见 `real_data.py` 模块 docstring 与
> `摸库交付_2026-09-15/04_文档/` 下的口径单。本文只讲**怎么跑、怎么验、别踩什么坑**。

---

## 0. 一句话背景（为什么会有两个站点）

同一份数据集，算 Pearson r 有三种都能算的口径，数字差很多：

| 口径 | 2000 年 pre6 全网格平均 | 是谁的能力 |
|---|---|---|
| 6 折**平均**（论文口径） | 0.145 | 一次训练的平均，**不是**任何单次训练 |
| 6 折**最大**（foldmax） | 0.363 | 逐格点挑最乐观折，**不是**任何一次训练 |
| **只取折 1**（fold1） | **0.0725** | ✅ **一次真实训练的结果** |

对外口径 = **fold1**（只有它对应一次真实训练）。
foldmax **保留仅为对照**，让人看见"逐格点挑最优折会把技巧放大 2.2~3.7 倍"这件事。

**⚠ 这里最容易出事的地方**：两个站点长得很像（同一个前端、同一份数据），
只有数字不同。**开错了不会报错，只会悄悄给你另一套数**。所以下面每一步都配了自检。

---

## 1. 开之前：先确认"没在跑别的东西"

这个项目历史上留下过几个**旧代码的僵尸后端进程**（跑着改动之前的代码，
还在读坏批 `Dataset/pre7/`）。它们不会自己退出，会占着端口。

开之前先看一眼：

```bash
netstat -ano | grep LISTENING | grep -E ":(8000|8001|8002|8011|5173|5174|5175)\b"
```

- 看到 `8000` / `8011` 上**有**进程 —— 大概率是僵尸。**别用它**（见 §6.3）。
- 本文要用的是 **8001 / 8002 / 5174 / 5175**，四个端口。

---

## 2. 打开（四个终端 / 两个后端 + 两个前端）

> 所有命令都在**仓库根目录** `降水预测-新任务/` 下执行。
> 后端那两条命令里的 `DISPLAY_MODE=...` **不能省**，原因见 §6.2。

### 站点 A —— **对外口径（fold1）**，这是给人看的那个

```bash
# 终端 1：后端 A
cd backend
DISPLAY_MODE=fold1 python -m uvicorn main:app --host 0.0.0.0 --port 8001
```

```bash
# 终端 2：前端 A
cd 网站前端框架
VITE_API_BASE=http://127.0.0.1:8001 npx vite --port 5174 --strictPort
```

→ 浏览器打开 **<http://localhost:5174>**

### 站点 B —— **对照（foldmax）**，只看"放大效应"，不对外报数

```bash
# 终端 3：后端 B
cd backend
DISPLAY_MODE=foldmax python -m uvicorn main:app --host 0.0.0.0 --port 8002
```

```bash
# 终端 4：前端 B
cd 网站前端框架
VITE_API_BASE=http://127.0.0.1:8002 npx vite --port 5175 --strictPort
```

→ 浏览器打开 **<http://localhost:5175>**

### 几点说明

- **`--reload` 可加可不加**（加了对后端改代码自动重启）。加了也不怕，
  因为 `DISPLAY_MODE=` 是钉死的，重启后口径不变。
- **前端必须写 `npx vite --port ... --strictPort`**，不要用 `npm run dev`：
  那个脚本是裸 `vite`（见 `网站前端框架/package.json`），**收不到端口参数**，
  会去抢 5173，而且 Windows 下 Vite 只绑 `[::1]`（IPv6），跟别的进程容易撞。
- 两个前端**读的是同一份源码**，切 git 分支会同时影响两个（但前端代码是口径中立的，
  所以显示逻辑不变，变的是后端给什么数）。

## 3. 自检：怎么确认你开对了（**最重要的一节**）

前端页面上没有"当前口径"的字样 —— **别靠眼睛看**。用下面任一条验。

### 3.1 最快的一条：看「实验统计表」有几行

| 站点 | table 行数 | experiment 列 |
|---|---|---|
| **A（fold1）** | **1** | `[1]` |
| **B（foldmax）** | **6** | `[1,2,3,4,5,6]` |

命令行验：

```bash
curl -s "http://127.0.0.1:8001/api/run?year=2019&lead=pre6" | python -c "import sys,json;print(len(json.load(sys.stdin)['table']))"
# 期望输出：1

curl -s "http://127.0.0.1:8002/api/run?year=2019&lead=pre6" | python -c "import sys,json;print(len(json.load(sys.stdin)['table']))"
# 期望输出：6
```

### 3.2 完整自检表（2026-09-19 实测，year=2019 lead=pre6）

| 指标 | A（8001，fold1） | B（8002，foldmax） |
|---|---|---|
| table 行数 | **1** | **6** |
| skillMap 全网格平均 r | **0.0725** | **0.2361** |
| 格点 (40,50) 时序 r | **0.2621** | **0.8217** |
| S2S 的 LSTM 那根（2003 年 pre5~pre9） | 0.349 / 0.349 / 0.341 / 0.349 / 0.363 | 0.514 / 0.505 / **0.341** / 0.508 / 0.504 |

一行脚本全打出来：

```bash
python - <<'PY'
import json, urllib.request
import numpy as np
for port in (8001, 8002):
    g = lambda p: json.loads(urllib.request.urlopen(f"http://127.0.0.1:{port}{p}", timeout=60).read())
    d, ts = g("/api/run?year=2019&lead=pre6"), g("/api/grid?i=40&j=50&year=2019&lead=pre6")
    print(port, "table", len(d["table"]),
          "| skillMap均值", round(float(np.array(d["skillMap"]["data"]).mean()), 4),
          "| 格点r", ts["r"])
PY
```

### 3.3 判据速记

- **table 出 1 行 ⇒ fold1；出 6 行 ⇒ foldmax。** 这一条就够。
- skillMap 全网格平均在 **0.07 上下** ⇒ fold1；在 **0.24 上下** ⇒ foldmax。

## 4. 两个口径在代码里差在哪

**只有一个落点**：`backend/real_data.py` 的 `_display_folds()`。

```python
def _display_folds(lead, year):
    folds = _folds(lead, year, "pearson2")
    if not folds:
        raise DataNotFoundError(...)
    if DISPLAY_MODE == "fold1":
        if 1 not in folds:                     # 缺折 1 直接报错，
            raise DataNotFoundError(...)       # **不静默换折**
        return [1]
    return folds                                # foldmax：实有折全要
```

四个 `gen_*`（skillMap / timeSeries / resultsTable / S2S 的 LSTM 曲线）**都与口径无关**，
它们统一调 `_display_pearson()` / `_display_series()`。fold1 时这两个函数里的
`np.fmax.reduce` 和 `np.mean` 对单元素退化为恒等 —— 所以**两个口径的差异真的只有上面这一处**。

开关本身：

```python
DISPLAY_MODE = os.environ.get("DISPLAY_MODE", "foldmax")   # main 分支的默认
if DISPLAY_MODE not in ("foldmax", "fold1"):
    raise ValueError(...)                                  # 非法值 → 直接起不来
```

### git 分支与这两个站点是什么关系

| 分支 | `DISPLAY_MODE` 默认值 |
|---|---|
| `main` | `"foldmax"` |
| `feature/display-single-fold` | `"fold1"` |

**两条分支只差这一行的默认值**（`git diff main..HEAD` 就是 1 行），
`backend/test_api.py` 两边逐字节一致。

> **⚠ 但服务器一旦显式带了 `DISPLAY_MODE=`，就与它所在的分支无关了。**
> 所以**推荐的用法是永远显式带上**（§2 就是这么写的）；
> 不带的话，带 `--reload` 的进程在你 `git checkout` 切分支时会
> **重载成另一套口径，页面数字悄悄变**，而这正是本文开头说的那个坑。

## 5. 数据从哪来

- 两个站点读**同一份** `Dataset/`（默认 `../Dataset`，可用环境变量 `DATA_ROOT` 覆盖）。
  **不复制、不写入、不修改**，磁盘上一个字节都不动。
- 两个后端进程**各持自己的 LRU 缓存**（容量 48 个文件条目 ≈ 171MB），互不影响。
- `Dataset/pre7/` 是**坏批**（CIO 输入是常数垃圾场），**网站不读它**；
  实际读的是修复批 **`Dataset/pre7-new/{year}/`**（见 `real_data.py` 的 `LEAD_DATA_DIRS`）。
- pre7 修复批现为 **1 折**（折 2~6 补齐中），折数一律用 `_folds()` 实查、**任何地方都没写死**。
  这**不影响**两个站点的口径 —— 折 1 口径与折数多少无关。

## 6. 常见坑（症状 → 原因 → 对策）

### 6.1 两个页面数字一模一样

- **症状**：5174 和 5175 看起来完全一样。
- **原因**：多半是两个前端打到了**同一个后端**。忘了 `VITE_API_BASE` 时，
  前端会回落到默认的 `http://localhost:8000`（`App.jsx:17`）。
- **对策**：按 §3 自检。另可确认前端有没有吃到环境变量：
  ```bash
  curl -s "http://[::1]:5174/src/App.jsx" | grep -n "const API_BASE"
  ```
  Vite dev 会在每个模块顶部注入 `import.meta.env = {...}`，用 `[::1]` 而不是 `localhost`
  去连（Vite 只绑 IPv6）。

### 6.2 页面数字"自己变了"

- **症状**：昨天看是 0.0725，今天变成 0.2361，没人改代码。
- **原因**：后端启动时**没带** `DISPLAY_MODE=`，跟着所在分支的默认值走；
  期间有人 `git checkout` 切了分支，带 `--reload` 的进程重载后换了口径。
- **对策**：**起后端永远显式带 `DISPLAY_MODE=`**（哪怕当前分支的默认值就是你想要的）。

### 6.3 页面上的 pre7 出 6 行 / 数字对不上

- **症状**：选 `pre7` 时 table 出 6 行（应该是 1 行）。
- **原因**：你连上的是**旧代码的僵尸进程**（占用 8000 / 8011 的那种），
  它跑的是 `LEAD_DATA_DIRS` 改动之前的代码，**还在读坏批 `Dataset/pre7/`**。
- **对策**：确认自己连的是 8001 / 8002。僵尸进程要清就清，但**先确认它不是别人正在用的**：
  ```bash
  netstat -ano | grep LISTENING | grep ":8000"     # 拿到 PID
  taskkill //PID <PID> //F //T                     # Git Bash 下参数是双斜杠
  ```

### 6.4 后端起不来，报 `DISPLAY_MODE 只能是 'foldmax' 或 'fold1'`

- **原因**：`DISPLAY_MODE` 拼错了（比如 `Fold1`、`fold_max`、`fold-1`）。
- **这是故意的**：取值非法时**直接抛错、不静默回落** —— 悄悄换口径比起不来危险得多。
- **对策**：改成 `fold1` 或 `foldmax`，全小写、无连字符。

### 6.5 前端起不来 / 占了别的端口

- **原因**：用了 `npm run dev`（裸 `vite`，没有端口参数），或者没加 `--strictPort`。
- **对策**：一律 `npx vite --port 5174 --strictPort`。

### 6.6 后端 `python main.py` 起在了 8000

- **原因**：`main.py` 末尾是 `uvicorn.run(app, host="0.0.0.0", port=8000)`，端口是写死的，
  它**不接受**端口参数。README 里那条 `python main.py` 是老用法。
- **对策**：要换端口就用 `python -m uvicorn main:app --port 8001`。

---

## 7. 关掉

四个终端各按一次 `Ctrl+C` 即可。或者在 Git Bash 里按端口找 PID 再杀：

```bash
netstat -ano | grep LISTENING | grep -E ":(8001|8002|5174|5175)\b"
taskkill //PID <PID> //F //T
```

**注意**：`taskkill` 在 Git Bash 下要写成 `//PID` / `//F` / `//T`（双斜杠），
写单斜杠会被 MSYS 当成路径改写掉。

## 8. 跑测试（可选）

`backend/test_api.py` 的 `API` 可由 `API_BASE` 环境变量覆盖，
所以**可以逐个站点验**（期望值按该分支的 `DISPLAY_MODE` 现算，不写死）：

```bash
cd backend
API_BASE=http://127.0.0.1:8001 python test_api.py    # fold1 站点，应 29/29
API_BASE=http://127.0.0.1:8002 python test_api.py    # foldmax 站点，应 29/29
```

（注意：在 `main` 分支上本地跑时，脚本内 `import real_data` 的默认口径是 `foldmax`，
对 8001 那条会不符 —— 要么在分支上跑，要么临时 `DISPLAY_MODE=fold1` 跑。
上面两条命令在**分支 `feature/display-single-fold`** 上是全绿的。）
