# CIO+LSTM 降水预测网站

网页端复现 CIO+LSTM 降水预测系统（东亚/印度季风季节内尺度技巧性预测演示）。

## 目录结构

| 目录 | 说明 |
|------|------|
| `backend/` | FastAPI 后端 API（端口 8000） |
| `网站前端框架/` | Vite + React 前端（端口 5173） |
| `start.py` | 一键启动脚本（自动拉起前后端并做健康检查） |

## 启动方式

前置依赖：Python 3.x、Node.js。

```bash
# 一键启动
python start.py

# 或分别启动：
# 终端 1 —— 后端
cd backend
pip install -r requirements.txt
python main.py          # → http://localhost:8000

# 终端 2 —— 前端
cd 网站前端框架
npm install
npm run dev             # → http://localhost:5173
```

浏览器打开 <http://localhost:5173/>

## ⚠ 展示口径：两个站点，别开错

同一份数据有两个展示口径，**页面长一样、只有数字不同、开错不报错**：

| 站点 | 口径 | 用途 |
|---|---|---|
| 对外 | **折 1**（一次真实训练） | 给人看、报数 |
| 对照 | **折最大**（逐格点挑最乐观折，**不是任何一次训练的能力**） | 只看放大效应 |

**同时开两个站点、怎么验自己开没开对、六个常见坑** —— 全部写在
**[`backend/两站点运行手册.md`](backend/两站点运行手册.md)**（保姆级，先读那篇）。

手动分别启动时注意两点：

- 后端要显式带 `DISPLAY_MODE=fold1`（或 `foldmax`），否则跟随 git 分支的默认值，
  带 `--reload` 的进程会在切分支时**悄悄换口径**；
- 前端换端口要用 `npx vite --port 5174 --strictPort`，**不要用 `npm run dev`**
  （该脚本是裸 `vite`，收不到端口参数）。

## 数据说明

- 真实数据目录 `Dataset/`（约 7200 个预计算 `.npy` 预测文件）**不入库**，需自行放回仓库根目录；缺失时依赖真实数据的接口（CIO/SkillMap 时序等）不可用，S2S 对比仍为 mock。
- 上传的 `.npy` 会落在 `backend/uploads/`（已 gitignore）。

## 模型权重放在哪（部署 / clone 后必读）

**权重体积大，不入库。** clone 下来只看网站和 `/api/run`、`/api/grid` 这类接口，
不需要它们；**在线推理**（`/api/chain/*` 那条链）必须有权重，否则模型清单里
每一组都会 `available: false`，页面上模型全不可选。

后端按**固定顺序**在三个"模型根"里找权重，**取第一个完整的组目录**：

| 顺序 | 根 | 内容 | 摆放方式 |
|---|---|---|---|
| 1 | `model/服务器模型_pt/`（仓库内） | 演示子集若干组 | clone 自带 |
| 2 | `E:/服务器模型_pt/` | pre1…pre20 × 2000–2013 | 外置盘，需自行提供 |
| 3 | `F:/服务器模型_pt/` | pre1…pre20 × 2014–2019 | 外置盘，需自行提供 |

- **目录布局**：`{根}/{lead}/{year}/NN_NNN.pt`，例如 `E:/服务器模型_pt/pre3/2003/00_000.pt`。
  目标网格是 `pre1`…`pre20` × `2000`…`2019` = **400 组**。
- **顺序即优先级**：某根上的组目录存在但**不完整**时会继续往后找下一根；
  同名组在多根上都有时，**永远读靠前的那个**（根顺序 = 版本优先级）。
- **完整性守卫**（三项全过才算"这一组完整"）：成员数 `8181`、字节和 `1558039617`、
  坐标覆盖 `81×101`。守卫只证**形状**、不证**内容身份**——放错版本的权重
  照样"通过"，只能靠根顺序自行控制。
- **例外**：`pre1/2000` 走**冻结 tar 归档**（`model/` 下），
  无条件压过任何目录根，`E:`/`F:` 上就算有同名目录也永远不读。
- **换位置**：env `MODEL_ROOTS`（多路径用 `os.pathsep` 分隔，Windows 上是 `;`）
  **整体覆盖**上面三条默认根，把权重放到任意盘、任意目录均可：

  ```bash
  MODEL_ROOTS="D:/weights/服务器模型_pt;G:/backup/服务器模型_pt" \
    DISPLAY_MODE=fold1 python -m uvicorn main:app --port 8001
  ```

- **根不可达时**：清单里每组给 `available: false` + `reason`，站点**继续可用**
  （技巧图/时序等读 `Dataset/` 的接口照常），只是模型选择器里这些组不可选。
  常见 `reason`：`模型根不可达（未挂载或目录不存在）`（盘没插 / 路径不对）、
  `不符（N != 8181）`（组存在但半截）。
- **插上盘之后**：根的存在性是**每次请求现探**的，但已扫过的组有按目录 `mtime`
  记忆化的缓存；挂载新盘后重扫是自动的，若发现清单没刷新，重启后端即可。
- 判"能不能用"**只认响应里的 `available` 字段**，不要用 `files` / `bytes` 自己反推。
- 扫描相关 env：`MODEL_PREWARM=0` 关预热（会连周期重扫与清单复用一起关掉）、
  `MODEL_SCAN_TTL`（默认 300s）、`MODEL_SCAN_BUDGET`（默认 4）。细节见
  [`backend/两站点运行手册.md`](backend/两站点运行手册.md) §10。
